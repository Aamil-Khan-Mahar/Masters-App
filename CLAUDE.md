# Masters — master's application workspace

Setting the app up or starting it for someone: follow `AGENTS.md`.

A local app for running a master's application cycle. This repo is the app only and is meant to be shareable; each user's own data lives in `data/`, which this repo ignores. Anything personal about the user (who they are, their cycle, how they like to work) belongs in `data/CLAUDE.md`, never in this file; a git-ignored `CLAUDE.local.md` containing `@data/CLAUDE.md` loads it in every session.

## Code vs data (keep this split)
- Repo (shareable): `app/`, `.claude/mcp-servers/`, `README.md` (setup), this file, `scripts/`.
- `data/` (the user's, git-ignored here; usually its own private git repo). Paths below like `Common/...` and `Applications/...` are relative to it:
  - `Common/` — personal, reusable material: `Profile.md` (frontmatter + summary), `Recommenders/<Name>/Info.md`, `Resume/{master-resume,resume}/` (LaTeX, `content-files/*.tex`), `Test-Scores/`, `Transcript/`.
  - `Applications/Programs/<Country>/<University>/<Program>/README.md` and `Applications/Scholarships/<Name>/README.md` — YAML frontmatter holds all tracked fields; body = notes + `## Research`. `SOP.md` / `SOP-Coach.md` sit beside a program's README.
  - `.app/` — the app's history (usage log, agent history, saved searches, FX cache).
  - `Private/` — never read, never touched.
- Never write user data outside the data root, never hardcode anything about a particular user (names, paths, schools, dates) in code, prompts or docs, and never `git add` anything under `data/` in this repo. `app/sample-data/` is fictional and is what the first-run setup can seed from.

## The app (`app/`)
- Start: `python app/start.py` (serves http://127.0.0.1:8000; rebuilds UI if sources changed). "Start it up" means run this in the background.
- Backend (`app/backend`, FastAPI, venv at `app/.venv`):
  - `store.py` — file data layer; `update_application` holds `WRITE_LOCK` (agents write in parallel).
  - `ai.py` — all Claude calls. Backend = Claude Code CLI on the subscription (`claude -p --output-format stream-json`), or the API if `ANTHROPIC_API_KEY` is set. Each task gets only its `BRIEF_FIELDS`; full resume only for score/SOP. Every agent runs on `MODEL` (Sonnet) by default; endpoints accept `{"strong": true}` to run on `MODEL_STRONG` (Opus).
  - `agents.py` — dispatcher: every AI task is an agent with a role/building (scout, researcher, recruiter, accountant, assessor, coach), max 3 working (`AGENTS_MAX`); waiting agents are formed but make no Claude calls until a slot frees up, live activity log, cancel, history in `<data root>/.app/agents.jsonl`.
  - `main.py` — API. `/api/applications/{id}/mission` = research team (skips parts researched < 30 days unless `force`).
  - `/api/applications/{id}/ask` = one targeted request ("add the IELTS minimum"): `ai.ask` may only change fields in `ai.ASK_FIELDS`, `main._ask_value` type-checks each change, and every ask is logged newest-first in the app's `asks` (shown by `components/AskClaude.tsx`).
  - `/api/tests/ask` = tests agent: a plain note ("booked IELTS for 12 Dec") and/or `read_reports` (PDFs in Common/Test-Scores via `store.test_reports`, which keeps only score lines; name/address/IDs never leave the machine) -> full updated `tests` list in Profile.md, logged in `tests_log`. Booked tests and expiry show on Up next, Calendar and the season map via `lib.testEvents`.
  - Essays: an app's `essays` list ({id, type sop|soi|personal|research|other, title, prompt, limit}); without one, `store.essays_for` derives a single statement (id `sop`, typed SOI when the prompt says so) so SOP.md stays attached. Files: SOP.md / SOI.md / Essay-<id>.md (+ `-Coach.md`). Routes `/essays/{essay_id}` (+ `/outline`, `/review`) must stay registered before the legacy `/sop` routes, which would otherwise swallow `.../essays/sop`. Coach guidance per type in `ai.ESSAY_GUIDE`.
  - Essay versions + comments (`components/EssayTools.tsx`, editor's History / Comments panels): snapshots in `<program>/Versions/<stem>/<YYYYmmdd-HHMMSS>.md` (frontmatter `label`, `auto`), taken on request, every `store.AUTO_VERSION_MINUTES` while saving, before a coach review, on "Mark final" and before a restore (a restore never loses the current draft). Comments are the applicant's notes pinned to a passage, in `<stem>-Comments.json`, saved with the text by `PUT .../essays/{id}` so offsets match; the editor shifts them as you type (`shiftComments`) and re-finds them by quote on load (`relocateComments`). "Review my draft" sends open comments to `ai.sop_review` as `<my_notes>` and the coach answers each under "Your notes".
  - Per-program resume (`resume.py`, `POST /api/applications/{id}/resume`, the Resume to-do in Apply): copies `Common/Resume/master-resume` to `<program>/Resume/`, Claude (`ai.resume_plan`) picks/orders whole entries by id only, `resume.build` re-joins verbatim chunks (text never edited), compiles with Tectonic (conda env `tectonic`), and cuts by `cut_order` until ≤ 3 pages. Result summary in README `resume`.
  - Final folder (`final.py`, `GET/POST /api/applications/{id}/final`, `/final/open`, `/final/file/{name}`; Apply's "Final folder" row under the to-dos): `<application>/Final/` holds the final version of every file to upload. Update fills it from what's already marked final (statements in `tasks_done`, typeset to PDF by `essay_pdf`; the resume once marked final), plus `Common/Transcript/*.pdf` and the `Common/Test-Scores` reports the program wants. Files the app added are listed in `Final/.final.json` and refreshed or removed with their source; anything else in the folder is the applicant's and never touched.
  - Faculty deep dive (`POST .../faculty-member/deep-dive`, `ai.faculty_deep_dive`, agent kind `faculty-deep`): in-depth profile written to `<program>/Faculty/<Name>.md`; the `## My notes` section is the applicant's and survives re-runs (`store.save_faculty_deep_dive`). Also refreshes the person's card and sets `deep_dive_on`. UI: Faculty tab, `?tab=faculty&person=<Name>`.
  - Supervisor emails (Apply, a supervisor's to-do, "Write email" = `?write=email`): essay id `email-<name>` (`store.supervisor_email`, mirrored by `lib.supervisorEmail`) is resolved by `main._essay` from the program's `faculty` list rather than `essays`, so it is never a to-do or in the Final folder, but uses the essay editor, versions, comments, coach pointers and review. File `Essay-email-<name>.md`; the coach brief (`ai._supervisor_brief`) adds the person's card, their deep dive and your contact notes; guidance in `ai.ESSAY_GUIDE["supervisor"]`.
  - Entry-requirements checklist (`requirements.py`, `POST .../requirements`, agent kind `requirements`): the app itself downloads the program page, statutes, annexes and forms (HTML/PDF/XLSX/DOCX via urllib + pypdf, since Claude's web reading can't open them), `ai.requirements_sources` names the documents, `ai.requirements_checklist` quotes every requirement verbatim with parts/status/how-to, one incremental follow-up round fetches annexes it asks for, and every quote is checked against the saved text (`quote_found`). Saved to `<program>/Requirements.md` (frontmatter = checklist, `mine` = your ticks/status/notes keyed by item key, kept across re-runs) + `Requirements/Sources/*.txt`; README `requirements_check` holds the summary. UI: "Entry requirements" tab (research + Apply program page) and `/requirements` (all programs, Europe by default, batch build via `POST /api/requirements/build`).
  - Courses (`store.courses`, `GET /api/courses`): parses `Common/Course-Outlines/Courses.md` (summary table, then `## Department` / `### CODE: Title` blocks with `- **Label:** value` facts, `**Learning outcomes**` / `**Topics and concepts**` / `**Texts**` lists, `**Tools:** …` fields); outline files in `Course-Outlines/Outlines/` are linked when the Outline fact names them. Course check (`POST .../course-check`, `ai.course_check`, agent kind `course-check`, Assessor): finds the program's official academic requirements (statutes, curriculum tables, credit minimums) on the web and rates each one met/partial/missing/unclear against your courses' topics; saved as README `course_check`. The mission always runs it (when Courses.md exists) unless it is fresh and Courses.md hasn't changed since; score sees its verdict.
- Frontend (`app/frontend`, Vite + React + TS + Tailwind v4): pages in `src/pages`, shared UI in `src/components/ui.tsx`, app state + job tracking in `src/data.tsx`. Build: `cd app/frontend && npm run build`.
- Three areas that never overlap (routes in `main.tsx`):
  - **Research** (`components/Layout.tsx`, sidebar): decides where to apply. Desk (`Desk.tsx`, `/`), Discover, Applications (`?view=cards|board|compare`, Researching + Shortlisted only; the board's last column "Applying" hands a program over), Scholarships (same rule), Costs (`Money.tsx`, `/money`, no fees), Agent Town, research program page `/app/<id>?tab=…` (Overview, Program, Faculty, Funding, Notes; Edit = Details, Deadlines, Faculty directory, Notes).
  - **Apply** (`components/ApplyLayout.tsx`, `/apply/*`): gets applications done, for stages `applyTasks.APPLY_STAGES` (Preparing, Submitted, Interview, Decision). Up next (`UpNext.tsx`), Applications (`Apply.tsx`: mail-style 3 columns, `?app=&item=`, `?folder=documents|scores|fees|supervisors`, `?page=program&tab=` = read-only program page), Letters (`Letters.tsx`), Calendar, Outcomes. To-dos are derived by `applyTasks.tasksFor` from existing fields (essays, recommenders, faculty contacts, admission.documents + documents_ready, tests + score_sends, checklist items you added, expenses, stage); essays/resume "final" live in README `tasks_done`. Research actions are hidden inside Apply via `readOnly.tsx` (`ReadOnly` context checked by ProgramProfile, FacultyDirectory, FundingTab).
  - **You** (`components/YouLayout.tsx`, `/you/*`, initials button in both modes): Profile, Tests (your scores against each program's minimum), Courses (`pages/Courses.tsx`: area ECTS, topic search, `?course=CODE` detail, each program's check verdict), Files. The check itself shows on the program page (`components/CourseCheck.tsx`, under Admission requirements) and as an Overview step/tile.
  - Handoff: "Start applying" (research page header + Overview) moves Shortlisted -> Preparing; "Back to shortlist" on Apply's program page. Old URLs (/calendar, /essays, /recommenders, /documents, /tests, /profile…) redirect.
- Tests live in Profile.md frontmatter (`tests`); per-app `score_sends` and `documents_ready` sit in each README.
- Design: "night season" — true black, white type, Newsreader (names/titles) + Public Sans (rem sizes; html is 17px from 2200px wide). Signals: yellow `accent` = act on it (one primary button per screen), red `danger` = urgent (≤14 days), blue `live` = links/selected/agents/focus. Tags are the only categorical colour: `<Tag family="tier|stage|rec|match|…" value=…>` via `TAGS` in `lib.ts` (reach red, target yellow, safety green). Everything opens something: `Row` (whole row links, chevron), `OpenLink`, `ExternalLink`. Rows under rules, boxes only for things you click/edit. No middle dots, no "→". Designed for 2560x1440 (`3xl`/`4xl` breakpoints) and iPhone 15 Pro Max (bottom tab bar + More sheet, safe areas). Sentence-case labels. Program pages are read-only dashboards; forms live behind Edit.
- Data root: `store.DATA_ROOT` = `DATA_ROOT` from `app/.env` (relative to the repo root) or `data/`. Until it has `Common/` and `Applications/`, the UI shows only the first-run setup (`pages/Setup.tsx`, `SetupGate` in `main.tsx`), which calls `POST /api/setup` → `store.init_data_root` (optional sample data, optional `git init`; refuses a data root the app's repo would track). `app/.local/` (gitignored) only holds the autostart log.

## Agent Town (done)
- Frontend job states are `waiting`/`working`/`done`/`error`/`cancelled` (`isActive` in `api.ts`). `data.tsx` has `runJob(strong => ...)`, `runMission`, `cancelJob`, `busyApp`, and a session-only `strong` ("Use Opus") flag shown by `components/OpusToggle.tsx`.
- Research buttons send a mission (team); "Research again" forces it. `/town` (`pages/Town.tsx`) = SVG village: buildings open dispatch menus, agents walk square → building with live activity bubbles, side panel has log + cancel, records list the history.

## Working conventions
- Keep token use low: verify UI by reading DOM/text, screenshot only when the visual matters; don't re-run AI research that's already fresh; test AI features on one small call.
- Never put secrets or Private/ contents in the app or prompts. Passwords are never stored.
- Don't commit unless asked.
